# Change/Reporting Variant Recipes

## V-A — Change request

**When this variant:** Mid-project, something needs to change (scope, schedule, budget, approach); formal change control process required; decision needs to be documented and approved.

**Audience:** Approval authority (per change-control policy: PM, sponsor, steering committee, etc.) + impacted teams.

**Variant-specific questions:**
1. What's the baseline being changed? (Need reference to the original scope/plan/budget)
2. Who has approval authority for this size of change? (Per change-control policy)
3. Is this a single change or part of a series? (Cumulative impact matters)
4. Timeline urgency? (Affects whether full analysis or expedited path)

**Variant-specific pitfalls:**
- Only presenting reasons to approve (advocacy disguised as analysis)
- Skipping "do nothing" as an alternative — it's almost always one of the options
- Missing cumulative impact (this change + 3 prior changes approved this quarter)
- Vague risks without mitigation
- Missing cost-of-rejection (focus only on cost of approving)

**Blind spots:**
- Second-order effects on adjacent projects sharing resources
- Customer / partner-facing implications (commitments that may need re-communication)
- Compliance / audit implications of the change itself

**Typical length:** 1-3 pages. Executive summary at top, detail follows.

## V-B — Status report

**When this variant:** Recurring project communication; sponsor/leadership needs visibility; decision points may emerge.

**Audience:** Sponsor, steering committee, sometimes wider distribution. Match formality to audience.

**Variant-specific questions:**
1. What's the reporting period? (Weekly / bi-weekly / monthly)
2. What's the distribution list? (Affects level of detail)
3. Is there a prior report to compare against? (Trend analysis)
4. Any specific decisions expected from this report?

**Variant-specific pitfalls:**
- Activity reporting (what we did) without outcome framing (what changed because of what we did)
- Sandbagging Green when it should be Amber (avoids hard conversation now, blows up later)
- Sugarcoating Red as Amber (same problem in opposite direction)
- No "decisions needed" section — leadership reads and moves on without knowing what to do
- Missing forward look (only retrospective on past period)

**Blind spots:**
- Risks that haven't materialized yet but should be on radar
- Team morale / capacity signals (not gossip, but observable: turnover, overtime, sick days)
- Dependencies on other teams / projects whose status may change

**Typical length:** 1-2 pages for weekly; 2-4 for monthly; longer for quarterly.

## V-C — Gap analysis

**When this variant:** Capability assessment, due-diligence, transformation planning, post-audit response, M&A integration prep.

**Audience:** Sponsor + execution team. Output drives a roadmap.

**Variant-specific questions:**
1. What's being assessed? (Capability, process, system, organization)
2. What's the target state, and where does it come from? (Strategy doc? Benchmark? Regulation?)
3. Current state evidence sources? (Audit, interviews, observation, data)
4. Recommendations expected as part of this deliverable, or in a follow-up?

**Variant-specific pitfalls:**
- Listing gaps without prioritization (flat list, no guidance)
- Recommendations not tied to specific gaps (orphan recommendations)
- Target state defined too vaguely to enable real comparison
- Ignoring the cost of closing the gap (every recommendation needs effort estimate)
- Missing "cost of not closing" — leaves decider without urgency signal

**Blind spots:**
- Capacity for change (team can't do 20 things at once — sequencing matters)
- Dependencies between recommendations (can't do X before Y)
- Non-obvious gaps in governance, data quality, skills (not just visible process gaps)

**Typical length:** 3-8 pages, depending on capability scope.

## V-D — SWOT analysis

**When this variant:** Strategic planning, annual review, market entry decision, competitive positioning analysis.

**Audience:** Leadership, board, strategic planners.

**Variant-specific questions:**
1. What's being analyzed? (Company / business unit / product / project / capability)
2. Time horizon? (SWOT changes over time)
3. Strategic context — what decision will this inform?
4. Evidence sources for external factors (opportunities/threats)?

**Variant-specific pitfalls:**
- Generic items ("good team", "strong brand") without evidence
- Mixing internal (S/W) with external (O/T) factors
- Listing without strategic implications (no TOWS)
- Confirmation bias — items selected to support a pre-formed conclusion
- Optimism bias — weaknesses and threats softened

**Blind spots:**
- Externalities — regulatory, technology, geopolitical shifts
- Adjacent / substitute threats (not just direct competitors)
- Long-tail strengths (capabilities you don't currently use but could)
- Capability decay — strengths that are eroding (talent attrition, tech obsolescence)

**Typical length:** 1-3 pages for the analysis + 1-2 pages for TOWS strategic implications.

## When variants compose

Common chains:
- **V-D → V-C → V-A:** SWOT identifies strategic moves → gap analysis on capability needed → change requests for specific projects to close gaps
- **V-B → V-A:** status report surfaces a problem → change request to address it
- **V-C → V-A:** gap analysis recommends actions → each major action becomes a change request

Produce as separate deliverables, not blended. Each has different rigor expectations and audiences.
